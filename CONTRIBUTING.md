# Contributing to Traymio

Bug reports, focused fixes, and usability improvements are welcome. Discuss large behavior changes before implementing them.

## Build on Windows

```powershell
.\scripts\build.ps1 -Test -Package
```

The build uses the .NET Framework compiler supplied with Windows. No NuGet restore is needed. Keep code compatible with that compiler unless a toolchain change is agreed separately.

| File | Purpose |
| --- | --- |
| `src/Shelf.cs` | Path collection, deduplication, undo, and Windows transfer payloads |
| `src/Traymio.cs` | Floating UI, drag/drop, clipboard, shortcut, and notification icon |
| `src/Tests.cs` | Synthetic fixtures, data-transfer checks, and UI handler tests |
| `src/Traymio.ico` | App icon, generated by the app's drawing code |
| `scripts/build.ps1` | Build, tests, release ZIP, and checksums |

Generated artifacts belong in ignored `dist/` and `artifacts/`. Publish binaries as release assets rather than source commits. The README screenshot uses synthetic sample items with demo paths.

## Validation

Automated tests generate their own files, check source integrity, inspect copy-only payloads, exercise UI handlers, and render the window. They do not use the real clipboard, register a global shortcut, or perform live Explorer dragging.

Manually verify these when changing integration behavior:

1. Drop files/folders from Explorer into Traymio, including multiple locations.
2. Drag a selection and all items into Explorer; confirm originals remain.
3. Copy/paste in both directions and check clipboard copy semantics.
4. Try duplicate names at the destination and preserve its normal prompts.
5. Move a source outside Traymio and check unavailable-item handling.
6. Exercise notification-area hide/reopen/exit and hotkey conflicts.
7. Check resizing, display scaling, mixed-DPI monitors, and network paths.

Do not turn copy operations into moves or delete user files as part of tray cleanup. Do not silently persist shelf paths or enable startup; those would require explicit product choices.

Include Windows version, scaling, destination app, and validation in your PR. Redact private paths in screenshots and use synthetic files in reports. Contributions use this repository's MIT license.
